# VELLUM 大书分页窗口续翻修复

## 问题

《哈利·波特》在深层目录跳转后使用 anchored window 分页。默认封面翻页和滑动翻页期间，`PageView.onPageChanged` 会被刻意忽略，原实现没有在翻页提交完成时触发下一批分页。当阅读到当前局部窗口尾部时，`PageView.itemCount` 停留在旧值，表现为约第 12904 页无法继续向前翻。

## 决策

- 把“翻页提交完成”作为分页扩展触发点：无动画、滑动和封面三种模式都在目标页写入后调用 `maybeExtendPagination()`。
- 继续使用现有阈值：当前页距离窗口末尾少于 24 页时，异步预取当前页之后最多 100 页；不在翻页动画中同步扫描整本书。
- 保留分页世代取消、anchored window、页码估算和 `ReadingState` 数据格式，不迁移已保存书籍或阅读状态。
- `PageView.onPageChanged` 仍负责用户可滚动事件；翻页动画路径由提交回调补齐，避免旧回调与新窗口互相覆盖。

## 验证

- 新增 `reader_page_window_extension_test.dart`，在预取尾部提交封面翻页并验证窗口增长。
- 新增目录深跳回归：跳转前先把旧 `PageController` 页索引同步收敛到新 anchored window，随后立即前进不会因为旧深页索引超出新窗口而丢失手势。
- `flutter analyze lib` 通过。
- 完整 `flutter test` 通过（320 项）。
- 模拟器验证使用当前 `emulator-5554` 用户数据；不卸载应用、不清除书籍数据、不执行 Git 操作。

## 实机深页复现结果

在 `emulator-5554` 的《哈利·波特》（46,978 段）中，切换到左右翻页后从目录选择深层结构项，阅读器落在第 `13388 / ~13497` 页。连续向前翻页推进到第 `13409 / ~13497` 页，内容、页码和分页窗口均继续更新；冷启动恢复深层位置也能正常进入首页并保持可用。页码估算仍保留 `~` 标记，分页完成后自动转为精确值。

## 章节首页前翻锁定修复

此前修复只覆盖了 anchored window 尾部的继续向后翻页，未覆盖章节首页的反向翻页。深层目录跳转会把分页窗口从章节段落开始，章节首页因此是局部页 `0`，窗口中没有任何前置页；点击路径把 `-1` 夹回 `0` 后直接返回，右向拖拽也会因为目标越界而提前结束。

本次采用有界前置回填：

- 局部首页发生前翻请求时，先从目标段落前 `256` 段建立新 anchored window；目标仍在局部页 `0` 时最多扩大到 `512` 段。
- 回填只测量限定范围，取消旧分页世代，并返回原章节段落在新窗口中的页索引；随后统一执行覆盖、平移或无动画翻页。
- 目录章节跳转和“继续阅读”预加载同一份有限前置内容；搜索、书签和笔记跳转保留精确段落语义，并在需要时按需回填。
- 点击、右向拖拽、音量键和覆盖翻页排队操作共用前翻边界处理；全书第一页没有前置内容时安全保持不动。
- 新窗口建立后同步 `PageController`、`currentPage`、`requestedPage`，旧异步分页和动画完成回调不得覆盖新窗口。

新增回归覆盖 46,978 段规模的有界前置回填、深层章节首页点击前翻、真实右向拖拽和返回章节首页。阅读状态 JSON、书籍 JSON、备份格式和已导入内容均保持兼容，不执行 Git 操作。
